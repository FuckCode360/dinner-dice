# Phase 01 计划

## 目标

交付一个可本地运行的 Dinner Dice MVP：用户能手动维护个人饭库，根据当前偏好摇出今天吃什么，并保存最近吃过记录。

## 本期修改范围

- 初始化 Vite + React + TypeScript 前端项目。
- 新增手机优先的单页应用界面。
- 新增本地饭库 CRUD 能力。
- 新增预算、距离、健康程度、辣度和堂食/外卖筛选。
- 新增加权随机摇号和最近吃过记录。
- 新增 JSON 导入导出，降低本地数据丢失风险。
- 新增三套抽卡页面主题，并接入项目内生成图片背景。

## 本期测试与验收

- 运行 `npm run build`，确认 TypeScript 和构建通过。
- 手动录入多条样例数据，验证筛选条件能影响候选池。
- 验证摇号后历史记录会更新，刷新页面后数据仍存在。
- 验证导出、清空、导入后能恢复数据。
- 在移动端尺寸检查页面没有横向滚动或明显遮挡。

## 不包含

- 不接入美团、饿了么或其他外卖平台。
- 不做账号、登录、云同步或多人共享。
- 不做地图 API、实时营业状态、配送费或自动价格抓取。
- 不做复杂营养分析。

## 验收标准

- 新用户打开页面后可以添加第一家店，并在摇号页摇出结果。
- 筛选条件无匹配时有清晰提示，并可一键放宽条件。
- 用户能导出和导入自己的饭库 JSON。
- 本地构建通过，手机宽度下主要操作可正常完成。

## 风险

- 第一版依赖用户手动录入，初始使用成本仍然存在。
- `localStorage` 不是长期备份方案，需要用户主动导出。
- 最近吃过只降低权重，不保证完全避免重复。
